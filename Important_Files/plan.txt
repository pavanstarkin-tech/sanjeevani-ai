# HealthExpress AI — App Flow & Screen Count

This version keeps onboarding **minimal**. We collect only essential information initially and allow additional health/professional information to be added later when required.

## 1. Overall App Structure

| Area                              | Screens |
| --------------------------------- | ------: |
| Common / Welcome / Authentication |   **7** |
| User App                          |  **30** |
| Doctor App                        |  **24** |
| **Total Mobile App Screens**      |  **61** |

> Some screens are shared components and can be reused between User and Doctor flows. The count above represents the planned functional screens, not every popup, bottom sheet, dialog, or confirmation modal.

## Hospital Onboarding — Admin

This is specifically added to your requirement.

**Admin → Hospitals → Add Hospital**

Collect:

* Hospital name
* Logo
* Address
* Map location
* Contact details
* Departments
* Specialties
* Facilities
* Operating hours
* Hospital verification
* Service availability

Then admin can add/manage:

**Hospital → Departments → Doctors**

Example:

```text
KIMS Hospitals
│
├── Cardiology
│   ├── Dr. A
│   └── Dr. B
│
├── Neurology
│   ├── Dr. C
│   └── Dr. D
│
├── Orthopedics
│   ├── Dr. E
│   └── Dr. F
│
└── General Medicine
    ├── Dr. G
    └── Dr. H
```

Doctors registering later can select these **admin-approved hospitals** from the hospital list.

### Recommended final count

**Mobile application: 61 functional screens**

* **7 common**
* **30 User**
* **24 Doctor**

**Admin:** separate web application with approximately **13 major modules**, each containing multiple list/detail/create/edit screens.

The most important design decision is to **keep registration short**: name + mobile initially. Health information and doctor-professional information should be collected **progressively when needed**, rather than making onboarding a long form.
